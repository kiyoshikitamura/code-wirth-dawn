# spec_v26: 非同期PvP（闘技場モード）システム仕様書

**Version**: 1.0  
**Date**: 2026-07-07  
**Status**: Draft Specification  

---

## 1. 概要 (Overview)

エンドコンテンツである「コロシアム（闘技場）」に、新たに他プレイヤーの登録したパーティと戦う **「非同期PvP（闘技場モード）」** を実装する。  
プレイヤーは自身の現在のパーティと装備で、同じ実力帯（ランク）の他プレイヤーの「防衛パーティ（AI操作）」に挑戦し、真剣勝負を楽しむことができる。同期通信サーバーは不要で、既存のバトルエンジンを拡張する形で実現する。

---

## 2. 導線と画面遷移 (Routing & UI Flow)

拠点の施設グリッドにある「コロシアム」ボタンをタップした後の遷移フローを以下のように定義する。

### 2.1 コロシアム初期画面の選択肢
コロシアム起動時、プレイヤーに挑戦するモードを選択させるダイアログを表示する。

- **画面配置**: 
  - **左側:「対人戦」**（他ユーザーの防衛デッキと真剣勝負）
  - **右側:「ボス戦」**（難易度別の勝ち抜きモンスターバトル）
  - ※ 括弧付きの (PvP) や (PvE) というシステム的な表記は一切行わない。
- **遷移先**:
  - 「ボス戦」を選択した場合は、従来のコロシアム難易度選択（Easy/Normal/Hard）へ進む。
  - 「対人戦」を選択した場合は、新設する専用の **「対人戦（アリーナ）モーダル」** を起動する。

### 2.2 対人戦アリーナモーダルの構成
対人戦専用のモーダル内には以下の要素を集約する。

1. **挑戦者の現在戦闘スコアとランク表示**:
   - プレイヤーの現在のパーティ構成・装備を基にリアルタイム計算された戦闘スコアと、それに対応するランク（C/B/A/S）を表示する。
2. **手動防衛登録・更新ボタン**:
   - 任意のタイミングで現在のパーティ構成・装備・スキルデッキを「防衛パーティ」として上書き保存できるボタン。
3. **対戦相手マッチングリスト**:
   - 挑戦者と同じランクに属する他の防衛パーティ（またはゴースト）を3〜5名分リスト表示する。
   - 各対戦相手の「挑戦」ボタンを押すと、戦闘（`BattleView`）が開始される。

## 3. 防衛パーティの登録・更新仕様 (Defense Party Lifecycle)

ユーザーが意図的に防衛デッキと挑戦デッキを使い分けられるようにするため、**「自動登録・更新」は廃止**され、プレイヤーが明確な意思を持って能動的に登録・更新を行う**「手動登録」**仕様とする。

### 3.1 初回アクセス時の防衛登録必須化
- コロシアムの「対人戦」に初めてアクセスする際、防衛パーティの登録が完了するまで対戦相手マッチングリストへの挑戦がロックされる。
- 初回アクセス時は「現在のパーティを登録する」ボタンが強調表示され、登録を完了させることでマッチングリストが解放される。一度登録が完了すれば、次回以降この必須登録画面はスキップされる。

### 3.2 アリーナモーダル内での手動更新と防衛確認
- プレイヤーがPvP向けに装備やスキルデッキ、同行メンバーを変更した際、対人戦モーダル内の「防衛登録を更新」ボタンをタップすることで、現在の最新パーティ構成・装備品・スキルデッキ・同行メンバー情報を防衛スナップショットとして上書き保存（Update）できる。
- 「防衛構成を確認」ボタンをタップすることで、自分が現在登録している防衛パーティの装備・スキルデッキ・同行メンバーのステータスやスキル構成を自分自身でプレビュー確認できる。

### 3.3 防衛側の勝敗履歴と対戦ログ確認
- 自分の防衛パーティが他の冒険者から挑戦された際の勝敗結果および対戦ログ（ターンごとの戦闘テキストログ）を、「防衛履歴(勝敗)」ボタンから過去最大10件分さかのぼって詳細確認できる。

## 4. 戦闘評価スコアリングとマッチングシステム

対戦が一方的にならず、プレイヤーの育成進捗に応じた適正なバトルを実現するため、戦闘力を数値化してマッチングを行う。

### 4.1 戦闘評価スコア（Party Score: PS）の算出
各キャラクター（プレイヤー自身、および現在同行しているアクティブなパーティメンバー最大3名）のステータスから、キャラクター評価点（CS: Character Score）を算出し、その合算値をパーティ合計スコア（PS: Party Score）とする。

$$CS = HP_{max} + (ATK_{final} \times 10) + (DEF_{final} \times 10)$$
$$PS = \sum CS$$

- ※ $ATK_{final}$ および $DEF_{final}$ は、装備品のパッシブ補正やバフを反映した戦闘開始時点の最終実数値である。

### 4.2 ランク判定閾値
合計スコア $PS$ に基づいて以下の4つのランクに分類する。

* **Cランク**: $PS < 1500$ (初心者〜序盤パーティ)
* **Bランク**: $1500 \le PS < 3000$ (中盤パーティ)
* **Aランク**: $3000 \le PS < 5500$ (終盤・実力派パーティ)
* **Sランク**: $5500 \le PS$ (極限ビルドパーティ)

### 4.3 マッチングと過疎対策（ゴースト補填）
- 対戦相手リスト取得API (`/api/pvp/opponents`) は、挑戦者と同じランクに属する他の防衛パーティ（`pvp_defense_parties`）からランダムに 3〜5 件を抽出して提示する。
- **NPCゴーストシステム**:
  - 同ランクの防衛パーティがDB上に十分に存在しない場合（特に最下位C帯や最上位S帯）、あらかじめ定義された難易度別の「NPCゴーストパーティ（偽装プレイヤー）」で自動的にリストの空き枠を補填する。
  - ゴーストはランクに応じたプリセットのステータスとスキルデッキを持ち、挑戦画面では実在のプレイヤーと同様に提示される。

## 5. データベース設計 (Schema Design)

### 5.1 `pvp_defense_parties`（防衛パーティテーブル）

```sql
CREATE TABLE IF NOT EXISTS public.pvp_defense_parties (
    id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
    user_id UUID NOT NULL REFERENCES public.user_profiles(id) ON DELETE CASCADE,
    user_name TEXT NOT NULL,
    avatar_url TEXT,
    
    -- 戦闘評価スコアとマッチング用ランク
    battle_score INTEGER NOT NULL DEFAULT 0,
    defense_rank TEXT NOT NULL DEFAULT 'C' CHECK (defense_rank IN ('C', 'B', 'A', 'S')),
    
    -- プレイヤー自身のステータススナップショット（HP, ATK, DEF, 職業, レベル等）
    player_snapshot JSONB NOT NULL DEFAULT '{}'::jsonb,
    
    -- パーティメンバー（NPC）のリストスナップショット（各メンバーのステータス, inject_cards 等）
    party_members_snapshot JSONB NOT NULL DEFAULT '[]'::jsonb,
    
    -- プレイヤーの装備品スナップショット
    equipped_items_snapshot JSONB NOT NULL DEFAULT '[]'::jsonb,
    
    -- プレイヤーのスキルデッキスナップショット
    skill_deck_snapshot JSONB NOT NULL DEFAULT '[]'::jsonb,
    
    registered_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- インデックス
CREATE UNIQUE INDEX IF NOT EXISTS idx_pvp_defense_parties_user_id ON public.pvp_defense_parties(user_id);
CREATE INDEX IF NOT EXISTS idx_pvp_defense_parties_rank ON public.pvp_defense_parties(defense_rank);
```

## 6. バトル中の挙動とバランス調整 (Battle Specs)

### 6.1 防衛側へのHPバランス補正
防衛側の全キャラクター（プレイヤー＋メンバー）は、戦闘開始時に最大HPおよび現在HPが以下の式に従ってスケーリングされる。

$$\text{HP}_{final} = \text{HP}_{base} + (\text{HP}_{base} \times 5) = \text{HP}_{base} \times 6$$

- **仕様**: この補正はバトルエンジン初期化時に一時的に乗算適用され、データベース上の防衛データには影響しない。

### 6.2 防衛側AI（英霊AIの完全適用）
防衛側のキャラクターはすべて **`smart` AI Grade** で制御される。
- **AP消費判断とコンボ**: APを貯蓄し、1ターンに最大2回カードを使用する。
- **緊急回復**: 自身または防衛メンバーのHPが50%未満になった場合、回復カードを優先使用する。
- **ターゲット集中**: プレイヤー側の最もHPの少ないキャラクターを優先攻撃する。
- **レガシースキル**: レベルに応じたターン開始APボーナス（AP+1〜+2）を発動する。

## 7. バトルUI（防衛側エリア）の最適化

敵陣営も、プレイヤー側と同様の **「キャラクターアイコン並び（丸型アバター ＋ HPバー ＋ 名前）」のUIに最適化** する。

### 7.1 操作の衝突回避（ターゲット中再タップ方式）
敵アバターのタップ操作において、ターゲット指定とステータス詳細確認を競合させないための二段階アクション。

1. **ターゲットされていない敵アイコンをタップ**: 攻撃対象（ターゲット）に設定する。
2. **すでにターゲット状態の敵アイコンをタップ**: そのキャラクターの「詳細ポップアップ」を表示する。

### 7.2 詳細ポップアップでのHP補正の明記仕様
詳細ポップアップ内のHP表示では、ゲームバランス上の補正が乗っていることを明示するため、**ベースHP** と **PvP補正値** を併記する。

* **表示テキスト例**:
  `HP: 1,200 / 1,200 (ベース: 200 + PvP補正: +1,000)`
* **その他の表示情報**:
  - キャラクター名、職業、レベル、攻撃力（ATK）、防御力（DEF）
  - 装備中の所持スキルカード名一覧

## 8. 詳細プレビューポップアップの仕様 (Preview Popup)

対人戦の挑戦・防衛確認画面において、各キャラクターおよび同行メンバーの情報を詳細に確認できるポップアップを実装する。

### 8.1 プレイヤー（リーダー）の詳細
- 装備中の武具（スナップショットからマッピング解決された武器、防具、アクセサリー等）を常時展開して一覧表示。
- スキルデッキ（`user_skills` から取得され、防衛時にスナップショット保存された装備スキルカード）を一覧表示。

### 8.2 同行メンバー（お供NPC）の詳細
- コロシアムの挑戦/防衛確認リストでお供メンバーの行をタップした際、バトル中と同様のレイアウトのポップアップを起動する。
- **表示項目**: HP、攻撃力、防御力、クラス、レベル。
- **装備**: お供データスナップショットに含まれる `equipped_items_snapshot` から装備品をバッジ形式でプレビュー表示（ない場合は「装備なし」）。
- **スキル**: `signature_deck_snapshot` から、そのお供NPCがバトル中に使用する全スキルカード名をバッジ形式でプレビュー表示（ない場合は「なし」）。

## 9. API エンドポイント

### 9.1 `POST /api/pvp/defense`
現在のパーティ構成・装備・スキル（`user_skills`）をスナップショット化して防衛デッキとして手動登録・更新する。
- 競合防止のため、`user_id` カラムを onConflict ターゲットとした upsert 処理を行う。

### 9.2 `GET /api/pvp/defense`
自分が現在登録している防衛パーティデータ（スナップショット）を取得する。

### 9.3 `GET /api/pvp/opponents`
挑戦者の現在のパーティ構成から算出した戦闘ランクと一致する、他の防衛パーティ（またはゴースト）を取得する。
- **セルフヒーリング (自動同期機能)**:
  - マッチングされた対戦相手のうち、テスト・ダミーアカウント（「きたむ」や「コピー」を含むテスト用ユーザーID等）が検出された場合、データベースの実データ（`user_skills`, `inventory`, `party_members`）からリアルタイムに最新のスキルデッキや装備、お供の装備情報を再取得し、スナップショットを強制的に修復・同期させて返却（および防衛データに上書き保存）する。

### 9.4 `GET /api/pvp/defense-logs`
自分の防衛パーティが他の挑戦者に攻められた際の履歴およびターンごとの詳細テキストログを過去最大10件分取得する。

### 9.5 `POST /api/pvp/complete`
対人戦結果を検証・記録し、勝敗およびレート、連勝数等を更新する。
